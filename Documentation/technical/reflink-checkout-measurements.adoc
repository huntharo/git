Reflink stat-cache draft: measurements and correctness evidence
==============================================================

This is a design experiment, with a demonstrated correctness difference
from ordinary worktree creation. Passing the test suites does not establish
that stat-clean donors contain the requested blob. The APFS mmap experiment
below produces incorrect initial checkout bytes with an apparently clean
index. This draft is not evidence that removing verification preserves
PR #1's identical-checkout guarantee.

Revision and build controls
--------------------------

The starting live head of https://github.com/huntharo/git/pull/1 was
67675599f52e2d35bc55b9fcd8ec3cdd0e1c2bdd, against master at
50fe5cc63f9cd6e89b87a2c9ccf96a444f4cfdb7. This branch started there in a
separate worktree. PR #1 and its branch were not modified by this work.
The implementation is commit 3bddd57ca2, followed by measurement/report
and test-fixture updates. The production C source is unchanged by those
follow-ups.

PR #1 subsequently advanced to e590842f2eb441bc30ba98b33e23f96d5685610f.
The measurements use the pinned starting head, not that later revision.
The later revision includes filesystem-ID/subvolume eligibility changes;
cross-subvolume support from that revision is not part of this alternative.

Four separate builds per platform retain primary SHA1_DC. The default
build has no fast secondary SHA-1 implementation; the fast build adds
APPLE_COMMON_CRYPTO_SHA1_UNSAFE=1 on macOS or OPENSSL_SHA1_UNSAFE=1 on
Linux. These are secondary-hasher comparisons, not replacement of Git's
normal object-integrity protections. Original and alternative builds use
identical settings within each cell.

* Common: NO_RUST=1 NO_GETTEXT=1 NO_TCLTK=1; default -g -O2.
* macOS: NO_HOMEBREW=1 NO_DARWIN_PORTS=1
  CURL_CONFIG=/usr/bin/curl-config; system libcurl 8.7.1, zlib 1.2.12.
* Linux timing builds: Ubuntu 24.04 arm64, OpenSSL 3.0.13,
  libcurl 8.5.0, zlib 1.3; NO_OPENSSL is not set.
* Linux correctness build additionally uses NO_OPENSSL=1.

APFS runs use the local Mac M5 Max, 18 logical CPUs and 64 GB RAM,
macOS 27.0.1. Linux runs use a privileged Ubuntu container inside the
same host's Docker Linux VM (Linux 7.0.14-linuxkit), limited to four
vCPUs and 6 GB RAM. Eight checkout workers therefore oversubscribe the
Linux CPU quota. XFS and btrfs are separate 6 GiB sparse loopback images
on that VM's backing disk; XFS was formatted with reflink=1. This is real
Linux filesystem testing, not a native-disk or independent-cloud-machine
storage benchmark. Absolute cross-platform times should not be compared.

Timing matrices run sequentially without this task's test/build jobs
competing with them. Host activity is not globally controlled. Caches are
warm and no global cache purge is performed. Results include observed
variation rather than an inference of statistical significance.

Benchmark binaries were built before the implementation commit and can
report the starting revision with a .dirty suffix. The script records
source SHA-256, complete GIT-CFLAGS/GIT-LDFLAGS, and version output in
the raw JSON to distinguish them. Source fingerprints are:

Fixture and protocol
--------------------

The fixture is aws-cdk at 49839b28410f476646e2b60fe9fc5a570a540905:
14,541 tracked paths, 14,526 regular files, 14,469 nonempty regular
files and 15 symlinks. Fixture objects and source/recipient data are local
to the tested filesystem. Donor mtimes age naturally, and ordinary
update-index --refresh --force-write-index writes a real stat cache.
No donor stat information is fabricated.

contrib/reflink/benchmark.py measures worktree add --detach with either
--no-reflink or --reflink, checkout.workers=1 or 8, and parallel threshold
100. It uses each build's git executable directly, with explicit exec
and template paths, disabled global/system config and attributes, and
hooks disabled. Generated wrappers must point at the correct build;
copied wrappers were regenerated before secondary-build correctness tests.

Each of the 16 cells gets one excluded warm-up, then five repetitions,
interleaved in a reproducible shuffled order (seed 20261102). Both builds
have an ordinary-checkout control, so differences in the controls remain
visible. Wall/user/system time excludes validation and worktree removal.
Every run checks clean status. Each warm-up hashes all 14,526 regular
files with --no-filters and compares every result to the index blob ID,
outside the timer. Physical extent accounting also runs outside the timer.
Real-clone counters are required; scratch donors and verify-failed are
rejected. These runs all cloned 14,469 real files per reflink checkout.

The XFS reduction is substantial for this fixture. APFS does not establish
that cloning is consistently free: default one-worker and eight-worker
medians remain above contemporary ordinary checkout, with overlapping
and sometimes wide ranges. Native-secondary APFS medians also vary.
The implementations have different donor-integrity guarantees, so timing
alone does not select a winner.

Physical file data
-------------------

The helper reports private bytes, allocated bytes, regular-file count,
then completely shared regular-file count. Empty files require no data
allocation and are counted as completely shared. Directory/index metadata
and object storage are excluded. This is incremental recipient file-data
saving, not whole-repository disk usage.

[cols="1,1,4",options="header"]
|===
|Filesystem |Mode |private allocated files completely-shared
|APFS |normal-alternative |1159319552 1159319552 14526 57
|APFS |reflink-original |0 1159319552 14526 14526
|APFS |reflink-alternative |0 1159319552 14526 14526
|XFS |normal-alternative |1159319552 1159319552 14526 57
|XFS |reflink-original |0 1159319552 14526 14526
|XFS |reflink-alternative |0 1159319552 14526 14526
|btrfs |normal-alternative |1159319552 1159319552 14526 57
|btrfs |reflink-original |34840576 1159319552 14526 6020
|btrfs |reflink-alternative |34840576 1159319552 14526 6020
|===

APFS and XFS show zero private recipient file data in these warm-ups.
btrfs retains 34,840,576 bytes by this accounting, about 3.0% of the
ordinary allocation; the measured shared portion is 1,124,478,976 bytes.
All eight btrfs reflink warm-up cells reported the same allocation. Small
files can use inline extents: filefrag -s -v on a cloned 44-byte
.dockerignore reported last,not_aligned,inline,eof, without shared, and
a 4,096-byte FIEMAP length. The helper counts such extents as private;
these figures are file-extent accounting, not whole-volume metadata usage.

No-op tests additionally compare all recipient private/allocated data and
inode numbers before and after status, reset --hard, checkout -- .,
restore ., checkout-index -af and switch --detach HEAD. Reflink is disabled
for these subsequent operations, preventing a rewrite/reclone from hiding
lost sharing. Both configured worker counts pass on APFS, XFS and btrfs.

Correctness evidence and its limit
----------------------------------

contrib/reflink/mmap-race.py uses an already-dirtied writable mapping,
flushes it, ages actual file times, and lets Git commit/refresh the true
metadata. It then changes one byte through the mapping and compares
ordinary checkout, this alternative and the pinned original. The index
is written through Git; no index stat bytes are synthesized.

[cols="1,2,2,2",options="header"]
|===
|Filesystem |Source check after mmap edit |Alternative recipient |Ordinary / pinned PR #1
|APFS |mtime/ctime/inode unchanged; diff-files clean
|Wrong initial byte X; cloned=1; diff-files clean
|Correct byte A / correct byte A, verify-failed=1
|XFS |mtime/ctime changed; diff-files dirty
|Correct byte A; source-dirty fallback
|Correct byte A / correct byte A
|btrfs |mtime/ctime changed; diff-files dirty
|Correct byte A; source-dirty fallback
|Correct byte A / correct byte A
|===

Later donor mmap writes did not change recipient data on any filesystem.
On APFS ordinary reset --hard also retained the hidden donor edit. That
supports the stated stat-trust analogy for an existing file, but it does
not make creation of a different worktree equivalent: ordinary creation
reads the object database. This is a demonstrated extra donor race, not
merely a hypothetical warning. Current attributes also cannot establish
which historical conversion rules produced the donor's existing bytes.

The mechanism document traces unpack-trees' verify_uptodate_1 and
oneway_merge, checkout_entry_ca, ie_match_stat, racy timestamp handling,
refresh and update_ce_after_write. Existing destination metadata/index
integration already preserves no-op clones; copying donor timestamps into
the recipient or introducing another verification/cache framework is not
needed for that purpose.

Known-broken counts are existing TODO expectations; skipped tests are
included in totals and are not claimed as executed passes. Linux full
matrices preceded one new source-worktree-only filter case; that case
passed in the subsequent 137-case focused runs. The btrfs full run includes
it. The APFS aggregate results include focused reruns after fixing fixtures
found by the full runs, rather than claiming pristine initial full runs.

The original content assertions remain. Fixture fixes age real source files
before normal refresh; split-index setup must also age symlinks, because
update-index refresh marks an index changed if any entry is racy. The split
case establishes and checks its actual shared base and replacement bitmap;
it passed ten targeted repetitions after that fix. The ownership cleanup
recreates its file rather than attempting an unprivileged chgrp to an
inherited group unavailable to the user. On btrfs, the NOCOW failure-limit
test also needs a non-racy donor so it reaches the clone syscall; its
16-failure assertion is retained and passes. Focused suites pass without
the forced-reflink test environment as well as the full forced runs.

The existing suites cover visible dirty donors, preserved-mtime edits with
weak stat settings, assume-unchanged/skip-worktree, actual concurrent
source modification/path replacement, filters/encodings/CRLF/ident,
metadata/xattrs/ACLs where supported, sparse/split index, submodules,
worktree source lifecycle, parallel workers and unsupported fallbacks.
Racy donor tests explicitly decline cloning and verify correct independent
contents. These cases do not cover up the APFS mmap result above.

Reproduction
--------------

Use independent source/build directories for the pinned original and this
branch. Build each twice with the common flags above, adding only the native
secondary option for the fast build. Include all and t/helper/test-tool.
Do not reuse generated bin-wrappers pointing at another tree. Use a source
checkout of the exact fixture commit on the filesystem under test, allow
its mtimes to age, and use separate new output paths:

----
python3 contrib/reflink/benchmark.py --repo /fs/aws-cdk --output /fs/timings \
  --original-dc /build/original-dc --original-fast /build/original-fast \
  --alternative-dc /build/alternative-dc --alternative-fast /build/alternative-fast \
  --repetitions 5
python3 contrib/reflink/mmap-race.py --alternative /build/alternative-dc \
  --original /build/original-dc --root /fs/new-mmap-experiment
cd t
for suite in t241[0-4]-*.sh; do ./$suite --root=/fs/tests || exit; done
cd ..
GIT_TEST_REFLINK_CHECKOUT=1 make -j4 test DEFAULT_TEST_TARGET=prove \
  GIT_PROVE_OPTS=--jobs=4 GIT_TEST_OPTS=--root=/fs/tests
make unit-tests
----

Repeat the full suite with GIT_TEST_REFLINK_CHECKOUT=0 and corrupt as
applicable. Run tests as a normal user so permission checks execute. A
privileged VM/container is needed only to create/mount the Linux test
filesystems; the test user need not be root. Filesystem images and files
must be task-owned scratch data, never an existing user volume.
