EOL-aware reflink checkout: validation and measurements
======================================================

Scope and source
----------------

This extension starts at PR #2's verified draft/open head,
`d5db8771ce659822bd9fbb0911b600de1339fea3` (`feat/reflink-native-checks`),
whose master base is `50fe5cc63f9cd6e89b87a2c9ccf96a444f4cfdb7`.
The implementation is `1f0db625ed`; this report and the benchmark script
follow it. PR #1, PR #2, their history, the installed trial runtime and
application settings were not changed. Only this thread's isolated
worktree and scratch trees were used for mutable builds and fixtures.

The scope is EOL-only CRLF output. Matching converted donors share data;
no-op recipients keep PR #2's no-readback fast path. Recipient filters,
ident and encodings remain on the ordinary writer. Source configured
filters and encodings remain conservatively ineligible. Required/process/
delayed filters and LFS are not speculatively invoked or assumed to be
deterministic. No hash implementation, source index, or fabricated stat
metadata is introduced.

The implementation compares a converted clone with the ordinary recipient
output, using streaming explicit EOL conversion or in-core auto detection.
A comparison is necessary here because the index has no physical-EOL or
historical-conversion field. The source's current rules, a clean status,
and the same blob do not establish fresh checkout bytes. Reading the
clone after cloning avoids a separate comparison-to-clone donor race.
Unconverted candidates retain PR #2's stat-invisible-edit/APFS mmap limits;
this extension does not give them PR #1's stronger donor verification.

Builds and validation
---------------------

The APFS host is an ARM64 M5 Max running Darwin 27.0.0. Native builds used:

----
make -j4 DEVELOPER=1 NO_RUST=YesPlease NO_GETTEXT=YesPlease NO_TCLTK=YesPlease
----

The candidate source and a separate pinned PR #2 archive were built with
the same compiler options (`-g -O2`, developer warnings as errors).
Primary SHA-1 remains SHA1_DC; SHA-256 remains SHA256_BLK. No fast secondary
SHA-1 override was enabled. CFLAGS, LDFLAGS, version/build-options and the
SHA-256 of each build's `reflink-checkout.c` are recorded by the benchmark.

Linux validation uses the existing Ubuntu 24.04 ARM64 container on
Linux 7.0.14-linuxkit, with four CPUs and 6 GiB RAM. A distinct source copy
was built under `/tmp/conversion-mw0yw26e/build` with:

----
make -j4 DEVELOPER=1 NO_RUST=1 NO_GETTEXT=1 NO_TCLTK=1
----

Tests run as UID/GID 1000:1000 on existing real `/xfs` (`reflink=1`) and
`/btrfs` loop-device mounts. No remounts, new VMs or paid machines were
provisioned. Source and recipient fixtures are on the same tested real
filesystem. The parent read-only source/fixture mounts were not used as
mutable trees.

The new `t2415` has 34 cases covering fresh ordinary byte/mode/index
agreement, actual block sharing, explicit CRLF, autocrlf, auto binary/
mixed-EOL/no-newline detection, attributes changes in both directions,
distinct worktree EOL config, dirty/stale/racy donors, same-size edits with
restored mtime, concurrent donor writes and pathname replacement. Every
scenario runs with one and eight checkout workers. Existing suites cover
metadata, sparse/split index, submodules, source lifecycle, unsupported
filesystems and ordinary conversion/filter/parallel checkout behavior.

An offline integration fixture also used the existing Git LFS 3.7.1 ARM64
binary, with filter/hook configuration local to the scratch repository.
Ordinary and candidate checkouts at one/eight workers produced the exact
260,000-byte payload and clean status. The LFS file used the ordinary
writer and did not share, as required. No installed binary or global/app
setting was changed. Raw local evidence is under
`/private/tmp/reflink-converted-mw0yw26e/lfs/results.json`.

Native unit-test targets passed all 261 tests on macOS and Linux.

Only those extra sidecars in this task's Linux copy were removed, and the
complete clean suite was rerun. APFS fsmonitor tests use approved ordinary
macOS privileges rather than disabling checks.

Measurement method and tradeoffs
--------------------------------

`contrib/reflink/conversion-benchmark.py` creates independent fixtures and
interleaves ordinary PR #2 checkout (`--no-reflink`), PR #2 reflink checkout,
and candidate reflink checkout. Each fixture has 128 distinct 256 KiB raw
payloads; EOL-heavy splits them between explicit `eol=crlf` and
`text=auto eol=crlf`. An unconverted fixture controls the unchanged fast
path. Donors age naturally and receive normal index refresh. There are
five shuffled repetitions per fixture/control/worker cell, with a warm
cache and no global cache purge. Eight-worker runs set the parallel
threshold to zero. No other build/suite/benchmark from this work runs
during the recorded timing window.

Every checkout's SHA-256 bytes, modes, clean status and actual physical
allocation/sharing are checked outside its timed creation interval. A
separate untimed traced run per cell records conversion/compare cost.
`output-read-bytes` counts clone bytes actually read; the `compare-output`
region includes object reading, conversion and clone comparison. The sum
of region durations across workers overlaps in time for eight workers;
it is not checkout wall time or isolated CPU time. It measures the work
paid for output equivalence separately from avoided file-data writes and
private allocation. Successful converted candidates read/convert the blob
once, as ordinary checkout does, and additionally read the clone. Explicit
rules use bounded buffers; auto rules keep ordinary in-core memory use.
A mismatch repeats conversion in the fallback writer. Avoided allocation
is not a measured device-write count, and this work makes no blanket
speed claim.

The reproducible command is:

----
python3 contrib/reflink/conversion-benchmark.py \
  --pr2 /private/tmp/reflink-converted-mw0yw26e/pr2 \
  --candidate /Users/huntharo/.codex/worktrees/mw0yw26e/git \
  --output /private/tmp/reflink-converted-mw0yw26e/bench-final
----

----------------------

evidence and validation. There were 72 checkouts: 12 untimed evidence runs
and 60 timed runs. Timed creation intervals exclude validation, sharing

result, not a device-write measurement or a filesystem-wide free-space
promise. All converted bytes and modes matched the ordinary control.

Limitations
------------

Only APFS timing is measured here; Linux coverage is correctness/sharing
on XFS and btrfs. Windows cloning remains disabled. The experiment does
not change PR #2's stat trust for unconverted candidates, including the
known APFS mmap/stat-invisible donor failure. Source filters/encodings
and recipient non-EOL transformations remain fallbacks. Existing private
files skipped by normal checkout/reset are outside this extension's
scope; explicit existing-worktree re-sharing is a separate follow-up.
